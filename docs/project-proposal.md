## 1. Название и организация

- Название системы: Бронирование аудиторий
- Организация / подразделение: КГЭУ, учебный корпус
- № из таблицы примеров: 4

## 2. Главная сущность и справочник

- Главный объект (одна запись процесса): бронь аудитории
- Справочник (вторая таблица, ссылка числом): аудитория
- Поле-ссылка (как назовёте в JSON/БД): `auditoriumId`

## 3. Роли и права

| Роль | Создаёт | Назначает | Меняет статус |
| :--- | :--- | :--- | :--- |
| Преподаватель | да | нет | нет |
| Диспетчер расписания | нет | да | нет |
| Ответственный за аудиторию | нет | нет | да |

Исполнитель не назначает себя, если этого нет отдельным требованием.

## 4. Сценарий в одно предложение

Преподаватель создаёт бронь аудитории, диспетчер расписания назначает ответственного, ответственный меняет статус брони.

## 6. Что не входит в семестр

1. Печать бланков брони
2. Мобильное приложение
3. Интеграция с 1С
4. Оплата за использование аудитории
5. SMS-уведомления

## 7. Запас под ВКР

1. Данные/процесс: привязка брони к расписанию занятий с проверкой пересечений
2. Связи с другими системами: выгрузка броней в корпоративный календарь
3. Масштаб: бронирование нескольких корпусов с разными диспетчерами
4. Данные/процесс: статистика загрузки аудиторий по месяцам

## 8. Чем не копия соседа

Другой главный объект (бронь аудитории, не заявка на ремонт), другой справочник (аудитория, не участок), другие роли (преподаватель и диспетчер расписания, не диспетчер и инженер).
