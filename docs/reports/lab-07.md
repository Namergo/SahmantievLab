## DI

Сервис зарегистрирован через DI, чтобы контроллер не создавал реализацию через `new`:

```csharp
builder.Services.AddScoped<IRequestService, RequestService>();
```

## `/health` ≠ создание заявки

| Утверждение | да/нет |
| :--- | :---: |
| `/health` возвращает 200 без тела заявки | да |
| `/health` не принимает `title`, `campaignId`, `description` | да |
| Успешный `/health` не доказывает работу `POST /api/requests` | да |
| Создание главного объекта относится к ЛР8 | да |
| README прямо объясняет это различие | да |
| Swagger и `/health` проверены отдельно | да |

## Ответы на контрольные вопросы

- **Чем C# отличается от ASP.NET Core?** — C# это язык (файлы `.cs`). ASP.NET Core — web-фреймворк на .NET, который принимает HTTP-запросы и вызывает наш код. C# без ASP.NET Core — просто консольное приложение.
- **Зачем нужен DI, если можно написать `new`?** — DI позволяет заменить реализацию сервиса, не переписывая контроллер. Сегодня `RequestService` — заготовка в памяти; в ЛР8–ЛР10 вместо неё появится работа с PostgreSQL, а контроллер не изменится.
- **Что доказывает успешный `/health`?** — Только то, что процесс запущен и маршрут отвечает. Он не доказывает, что есть `POST /api/requests`, что проверяются поля, что данные сохраняются.
- **Почему создание заявки ещё не готово?** — По плану курса каркас и служебные адреса — ЛР7, контроллер главного ресурса и создание — ЛР8. Сегодня мы фиксируем инфраструктуру (порт, Swagger, DI), а не бизнес-логику.
